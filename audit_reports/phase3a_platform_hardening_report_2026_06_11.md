# PLATFORM HARDENING REPORT

Date: 2026-06-11
Branch: phase3a-platform-hardening-2026-06-11

## Goal

Prevent future CMS imports, specialty expansions, CPT updates, and generated artifact rebuilds from reintroducing data-integrity defects already remediated in Phase 0 through Phase 2D.

## Guardrails Added

- Added a single platform hardening gate: tools/platform_hardening_audit.py.
- Added DATA GOVERNANCE.md to document the canonical CMS source, import process, override policy, deleted-code policy, and validation process.
- Added a machine-readable integrity scorecard artifact generated by the audit command.

## Validations Added

The hardening command runs these validations:

- RVU validation
- indicator validation against CMS RVU26C
- deleted-code validation
- descriptor validation
- homepage/search validation
- Case Builder validation
- CPT page title, H1, and meta-description validation

## Failure Conditions

The command exits nonzero when any of the following are present:

- Active CPT page has a placeholder descriptor.
- Active CPT page has a missing descriptor.
- Active CPT has 0.00 RVU without inactive/deleted classification.
- Homepage search differs from cpt_database.json.
- Case Builder differs from cpt_database.json.
- Indicator fields differ from CMS RVU26C.
- Deleted/inactive CPT appears in active search.
- Deleted/inactive CPT appears in Case Builder.
- CPT page title, H1, or meta description is malformed.
